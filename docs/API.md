# Toucan API — v0.1

Backend for generating embeddable, ownable web animations for developer-educators.
v0.1 ships **all three** animation types end-to-end on a shared **spec/render**
pipeline:

- **`FLOW`** — Sequential Flow (the hero type): how something moves through an
  ordered series of stages (request lifecycle, bank transfer, agent loop, …).
- **`CODE_BLOCK`** — Animated Code Block: progressive reveal, line highlighting,
  annotations.
- **`DATA_STRUCTURE`** — operations on a basic structure (array, stack, linked
  list).

---

## What you get per animation

Each generated animation produces three deliverables:

| Deliverable      | How you get it                                   | Status   |
|------------------|--------------------------------------------------|----------|
| Hosted preview   | `previewUrl` — public, shareable HTML page       | ✅ v0.1  |
| Embed snippet    | `embedSnippet` — ready-to-paste `<iframe>`       | ✅ v0.1  |
| Code download    | `GET /api/animations/{id}/download` — full HTML  | ✅ v0.1  |
| MP4 export       | bundle is capture-ready; headless worker            | ⏳ later |

The animation HTML is **self-contained** (no external network deps), so it's
yours to host anywhere.

---

## Architecture: spec/render split

The LLM never writes animation code. Instead, per generation:

1. **LLM → JSON spec.** Given the prompt + chosen type, the model returns a JSON
   spec conforming to that type's schema. It decides only *content* (labels,
   order, counts, operations) — never timing, layout or motion.
2. **Validate / repair.** The spec is parsed and clamped into the v0.1-supported
   envelope (e.g. flows are 3–6 linear nodes; data structures ≤ 8 elements). An
   invalid spec triggers one re-prompt with the error before failing.
3. **Deterministic renderer → animation.** A hand-built, per-type renderer (our
   code, shipped as a static resource) consumes the spec. All motion-design
   polish lives here once, so every animation inherits it.
4. **Bundle.** The renderer + baked-in spec + theme are inlined into one
   self-contained HTML document — the preview, the download, and the MP4 source.

**Determinism (MP4-ready).** Every bundle has a known total duration and is
driven by a single master clock. It exposes `window.__duration` (ms) and
`window.__seek(ms)` — a pure function of time with no randomness or wall-clock
dependence — so a headless worker can step it frame-by-frame for capture.

The validated spec is persisted alongside the HTML (roadmap: a timeline editor
edits the spec and re-renders; style-memory swaps theme tokens — both nearly free
because content and render are separated).

## Generation provider

Animations are generated by an LLM behind the `LlmClient` abstraction.

The model only produces a JSON **spec** (not code), so the prompt is small and
cheap and the output is validated rather than executed.

- Default provider: **OpenAI / GPT-4.1** (`llm.provider=openai`)
- Configure with env var `OPENAI_API_KEY` (preferred) or `openai.api.key` in
  `application.properties`.
- If no key is set, the app falls back to a **deterministic stub** that emits a
  valid spec per type (request-lifecycle flow, Fibonacci memo, stack ops) so the
  whole pipeline runs offline.
- Switch to Claude any time with `llm.provider=anthropic` + `ANTHROPIC_API_KEY`.

| Property             | Default                       | Notes                          |
|----------------------|-------------------------------|--------------------------------|
| `llm.provider`       | `openai`                      | `openai` \| `anthropic` \| `stub` \| `auto` |
| `openai.model`       | `gpt-4.1`                     |                                |
| `openai.max-tokens`  | `16000`                       |                                |
| `openai.temperature` | `0.7`                         |                                |
| `app.publish.dir`    | `published`                   | where preview bundles are written |
| `app.publish.base-url` | `http://localhost:8080`     | base for `previewUrl`          |

## Auth model

All `/api/animations/**` endpoints require a JWT **bearer token**.
Get one by registering, verifying your email, then logging in.

Preview pages (`/preview/**`) are **public** — that's intentional, so links are
shareable without auth.

---

## Endpoints

Base URL: `http://localhost:8080`

### Auth — `/api/auth`

| Method | Path                          | Auth | Body                                  |
|--------|-------------------------------|------|---------------------------------------|
| POST   | `/register`                   | —    | `{ email, name, password }`           |
| GET    | `/verify?tokenId=&token=`     | —    | (from email link)                     |
| POST   | `/login`                      | —    | `{ email, password, rememberMe }`     |
| POST   | `/resend-verification-email`  | —    | raw string: `"you@example.com"`       |
| POST   | `/reset-password`             | —    | raw string: `"you@example.com"`       |

`POST /login` returns:
```json
{
  "token": "<jwt>",
  "user": { "...": "UserDTO" }
}
```

### Animations — `/api/animations` (JWT required)

| Method | Path                  | Description                                    |
|--------|-----------------------|------------------------------------------------|
| POST   | `/`                   | Create an animation — **async**, returns `PENDING` immediately |
| GET    | `/`                   | List your animations (newest first)            |
| GET    | `/{id}`               | Get one animation (poll this for status)       |
| GET    | `/{id}/download`      | Download the HTML (`Content-Disposition: attachment`) — legacy |

**Create request body:**
```json
{
  "prompt": "How an HTTP request travels from the browser to the database and back."
}
```
- `prompt` — required, non-blank, max 4000 chars.
- No `type` — locked decision 2 removed it. The user picks a prompt only; topic
  classification survives solely as an optional internal director hint.

**AnimationDTO response:**
```json
{
  "id": "f1e2d3c4-...",
  "prompt": "How an HTTP request travels...",
  "status": "READY",
  "mp4Url": "http://localhost:8080/preview/f1e2d3c4-.../render.mp4",
  "posterUrl": "http://localhost:8080/preview/f1e2d3c4-.../poster.png",
  "durationMs": 3000,
  "embedSnippet": "<video src=\"...\" poster=\"...\" controls ...></video>",
  "errorMessage": null,
  "createdAt": "2026-06-23T12:34:56"
}
```

**Status lifecycle:** `POST` reserves a `PENDING` row and returns instantly; an
async worker runs spec generation → validation → dispatch to the renderer, moving
the row `PENDING → GENERATING`, then the renderer's callback drives it to `READY`
(with `mp4Url` populated) or `FAILED` (with `errorMessage`). Poll
`GET /api/animations/{id}` until terminal. `mp4Url` / `posterUrl` / `durationMs` /
`embedSnippet` are `null` until `READY`.

> v0.1 note: the renderer currently returns a **placeholder MP4** to prove the
> async spine end-to-end. Real Remotion compositions land in Section 3.

### Internal — `/api/internal/**` (service-to-service, not user JWT)

| Method | Path                       | Description                                    |
|--------|----------------------------|------------------------------------------------|
| POST   | `/render-callback`         | The renderer's terminal callback (multipart)   |

Authenticated by a shared secret in the **`X-Internal-Token`** header
(`app.internal.render-token`), granting `ROLE_INTERNAL` — entirely separate from
the user JWT. A `READY` callback uploads the MP4 (+ poster) straight through to
the `PublishingService`; a `FAILED` callback carries the error. Not for end users.

## Postman quick start

### 0. Environment variables

In Postman, create an environment with:

| Variable  | Initial value           |
|-----------|-------------------------|
| `baseUrl` | `http://localhost:8080` |
| `token`   | *(left empty)*          |

### 1. Register

```
POST {{baseUrl}}/api/auth/register
Content-Type: application/json

{
  "email": "you@example.com",
  "name": "Your Name",
  "password": "supersecret"
}
```
Then open the verification link from the email (`GET /api/auth/verify?...`).

### 2. Login → capture the token

```
POST {{baseUrl}}/api/auth/login
Content-Type: application/json

{
  "email": "you@example.com",
  "password": "supersecret",
  "rememberMe": true
}
```

Add this to the request's **Tests** tab so the JWT is saved automatically:
```js
pm.environment.set("token", pm.response.json().token);
```

### 3. Create an animation

```
POST {{baseUrl}}/api/animations
Authorization: Bearer {{token}}
Content-Type: application/json

{
  "prompt": "How an HTTP request travels from the browser to the database and back."
}
```
Response comes back **immediately** as `PENDING`. Poll `GET /api/animations/{id}`
until `status` is `READY` (then `mp4Url` is set) or `FAILED` (then `errorMessage`).

### 4. Open the preview

Once `READY`, paste the `mp4Url` straight into a browser — no auth needed. Or grab
`embedSnippet` (a `<video>` tag) and drop it into any page.

### 5. List / fetch / download

```
GET    {{baseUrl}}/api/animations              Authorization: Bearer {{token}}
GET    {{baseUrl}}/api/animations/{{id}}       Authorization: Bearer {{token}}
GET    {{baseUrl}}/api/animations/{{id}}/download   Authorization: Bearer {{token}}
```
The download endpoint returns the raw HTML with a `.html` attachment filename —
in Postman use **Send and Download** to save the file.

---

## Notes & gotchas

- **`prompt` max length is 4000 chars** — longer prompts get a 400.
- **Auth header format is `Bearer <token>`** — no quotes, single space.
- A `FAILED` animation still persists; check `errorMessage` for the cause
  (e.g. missing/invalid OpenAI key, model error).
- Preview bundles are written to `app.publish.dir` (`published/` by default,
  git-ignored). In v0.1 they're served by Spring Boot itself; an R2 backend
  can replace `LocalPublishingService` later without touching callers.
